## Почему новый CB не совпал со старым

У старой опоры meanAP0.268277,у новой 0.268611. Q3 имеет тот же порядок и AP;
разница вероятностей не больше 1.39e-15. В Q4 реальные изменения прогнозов дали
+0.003993AP,а в Q1 -0.002991. Данные/схема/код/версии CatBoost1.2.10 совпали.
Все 3 старых checkpoint на текущих признаках воспроизводят 5815 старых OOF EXACT.
Причина различия обучения без серверных весов/фактических effectiveparams не
установлена; платформенная численная чувствительность — гипотеза.
Это не мешает новым парным сравнениям: оба архива используют один и тот же
новый reference EXACT. СтарыйVisit рассматривается как отдельный predictor.

## Следующий ограниченный запуск

Подтвердить только две сильные классические ветки на seed 17/2026;готовый seed 42
не повторяется. Это 12 новых внешних fit с прежними фиксированными 500 деревьями,
без внутреннего HPO и новых архитектур. Итог заранее задан: сначала среднее
вероятностей seed 42/17/2026 отдельно для reference иcompact,затем их rank50/50.
Нельзя выбирать лучший seed по dev. Это проверка устойчивости на прежнем dev,
не новая независимая validation.

```bash
cd ~/ml_hws_hw4
source .venv/bin/activate
mkdir -p logs
nohup python -u scripts/run_hw4_classical.py \
  --raw data --out analysis/hw4-cb-confirm-01 \
  --models cb_reference cb_compact --seeds 17 2026 --resume \
  > logs/hw4-cb-confirm-01.log 2>&1 &
```

Этот небольшой запуск CPU. Вернуть analysis/hw4-cb-confirm-01/return_results.tar.gz.

seed 42 и обе NN-серии сохранены и повторяться не должны. После устойчивости
зафиксировать финалиста/fallback до одноразового открытия 2024Q2/Q3;далее final
refit/CSV. Новые NN-архитектуры по текущим результатам не обоснованы.
