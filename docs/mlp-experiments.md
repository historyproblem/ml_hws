# Проверка регуляризации MLP

Сравниваем три вручную заданных варианта одной сети 128/64 с ReLU и Adam. Признаки, функция ошибки и временные границы общие. Новые алгоритмы и архитектуры автоматически не ищутся; итоговая конфигурация автоматически не выбирается.

| Вариант | L2 (`weight_decay`) | Dropout |
|---|---:|---:|
| `early_stop` | 0,0001 | 0 |
| `l2_stronger` | 0,01 | 0 |
| `dropout_10` | 0,0001 | 10% |

Все варианты используют batch size 1024 и learning rate 0,001. Параметры заданы в `configs/mlp_experiments.json`, общие параметры сети — в `configs/baselines.json`.

## Как выбирается число эпох

В каждой внешней проверке сначала используется отдельный более ранний срез:

| Внешняя проверка | Внутренняя проверка для остановки | Доступность меток внутреннего обучения | Доступность меток повторного обучения |
|---|---|---|---|
| 01.09.2018 | 01.08.2018 | `target_end <= 01.08.2018` | `target_end <= 01.09.2018` |
| 01.10.2018 | 01.09.2018 | `target_end <= 01.09.2018` | `target_end <= 01.10.2018` |

1. Масштабирование и заполнение пропусков обучаются только на внутреннем train.
2. Сеть учится на `log1p(spend_30d)`. После каждой эпохи измеряется RMSLE на внутренней дате.
3. Максимум — 200 эпох. Обучение останавливается после 20 эпох без улучшения хотя бы на 0,0001 RMSLE. Восстанавливаются веса выбранной эпохи.
4. Число выбранных эпох фиксируется. Новая сеть с тем же seed и заново обученным preprocessing обучается с нуля на всех строках, метки которых доступны к внешней дате.
5. Внешние ответы используются только для расчёта итогового качества.

Окна целевых меток, пересекающие внутреннюю дату, исключаются из внутреннего обучения. Признаки каждого объекта по-прежнему строятся строго до его `as_of_date`.

Три seed: 42, 123, 2026. Вместе с двумя датами это 18 внешних оценок и 36 обучений, поскольку каждая оценка включает выбор эпох и обучение с нуля. Фиксируются все результаты, а не только удачный seed. Сентябрь и октябрь уже использовались в предыдущих экспериментах; при интерпретации учитывать повторное использование этих дат.

## Команда для V100

Из корня актуального клона, в окружении Python 3.12 и с четырьмя официальными CSV в `data/raw/`:

```bash
git pull --ff-only
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu121
python -u -m spend_baselines mlp-experiment \
  --device cuda --threads 2 \
  --out-dir outputs/mlp-regularization --resume
```

Используется FP32. Seed и детерминированные операции фиксируются. Результаты CPU и CUDA могут немного различаться. CUDA-запуск не был проверен на V100 в текущей сессии.

Можно явно ограничить набор заранее выбранными вариантами и seed, например `--variants early_stop dropout_10 --seeds 42 123`. Короткий пробный запуск на CPU:

```bash
python -u -m spend_baselines mlp-experiment \
  --device cpu --threads 2 --epochs 2 --seeds 42 \
  --out-dir outputs/mlp-smoke --resume
```

## Что сохраняется

- `scores.csv`: внешняя RMSLE каждой конфигурации, даты и seed, выбранное число эпох, размеры выборок и время.
- `summary.csv`: среднее, стандартное отклонение, минимум и максимум RMSLE по seed отдельно для каждой даты. При одном seed стандартное отклонение не оценивается и остаётся пустым.
- `pooled_by_seed.csv`: объединённая RMSLE двух дат с весами по числу объектов. До окончания всех дат поле `n_folds` показывает неполное покрытие.
- `run_manifest.json`: точный план, версии, устройство, SHA256 кода и исходных файлов.
- Подкаталог каждой оценки: `selection_history.csv`, `refit_history.csv`, `validation_predictions.csv`, `result.json`, `checkpoint.pt`.

Checkpoint содержит веса после повторного обучения, архитектуру, seed и параметры preprocessing. Он относится к своей внешней дате; это не модель, обученная на всей истории перед ноябрьским тестом. Загрузка поддерживается через `TorchMLP.load(path, device="cuda")`; прогноз возвращается в шкале `log1p`.

`--resume` пропускает только полностью завершённые оценки с совпадающими SHA256 всех артефактов. Код, входные файлы, параметры, устройство и версии должны совпадать. При изменении плана или кода используйте новый `--out-dir`. Незавершённая оценка пересчитывается целиком; обучение с середины эпохи не возобновляется.

Данные, индивидуальные прогнозы и checkpoints остаются в `outputs/`, который исключён из Git. Загрузки в Kaggle эта команда не выполняет.

## Проверка реализации на CPU

9 ноября 2026 прошли 17 unit-тестов, включая временное исключение пересекающихся меток, восстановление выбранных весов, preprocessing только по train, загрузку checkpoint и проверки возобновления. Дополнительно выполнены все три варианта на обеих датах с лимитом две эпохи и seed 42; повторный запуск пропустил все шесть завершённых оценок без повторного обучения. Это функциональная проверка, не сравнение качества полных конфигураций.

Для варианта `early_stop`, seed 42, также выполнен полный CPU-запуск с максимумом 200 эпох и patience 20:

|---|---:|---:|
| 01.09.2018 | 24 | 2,631004 |
| 01.10.2018 | 11 | 2,701738 |

Это один вариант и один seed. Полный план из трёх вариантов и трёх seed на GPU ещё не запускался.
