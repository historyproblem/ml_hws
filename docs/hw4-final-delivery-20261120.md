## Зафиксированные кандидаты

До первой оценки ранее закрытых 2024Q2/Q3 записывается frozen_recipe.json
с SHA кода,данных,версиями,точными параметрами и правилом выбора.

- **A:** Context-CatBoost346 и Compact-CatBoost96,каждый с seed42/17/2026;
  сначала mean вероятностей внутри семейства,потом rank50/50 внутри квартала.
- **B:** равные трети рангов этих двух семейств и legacy VisitTransformer346.
  NN seed42,width64,2 слоя/4 головы,length16,AdamW.001/wd.01;ровно 2 эпохи —
  медиана прежних dev5/2/2,без выбора эпох на закрытых кварталах.
- Отдельные compact/context familymean CSV — компонентные диагностические
  отправки,не третий и четвёртый финалисты по закрытой проверке.

У CB прежние 500/depth5/lr.04/L2=10,CPU. Признаки и маски совпадают с проверенными
вариантами. У NN прежняя архитектура,math-only attention для воспроизводимости;
точное повторение старого обучения на другой платформе не обещается.

Правило выбора заранее: A основной; B получает приоритет только при AP>=A
в ОБОИХ новых кварталах и строго большем среднем AP. Веса/seed/эпохи после
просмотра этих кварталов не меняются. Далее Q2/Q3 считаются использованными,
новые опыты нельзя называть проверенными на прежнем нетронутом holdout.

Для каждого квартала модели обучаются только на прошлых строках. Старый
all-train public checkpoint никогда не используется для holdout-прогноза.
Для финального test-refit его seed42/reference можно повторно использовать
после проверки input/sourceSHA,параметров и воспроизведения старого testCSV.
Другие full-refit получают все 21017 размеченных строк. Ни один target теста
не восстанавливается и не используется.

## CSV и проверка

Основной скрипт создаёт:

1. submission_01_cb_rank50.csv
2. submission_02_cb_visit_rank3.csv
3. submission_03_compact_cb.csv
4. submission_04_context_cb.csv

Отдельный scripts/export_hw4_visit_diagnostic.py экспортирует уже обученную
компоненту в submission_05_visit_transformer.csv,без fit и новых holdout-метрик.
У него отдельный diagnostic_manifest.json; исходная заморозка и выбор A/B
не изменяются. Пятый слот можно использовать для него после приёмки первых
файлов,пока держать как резерв на техническое исправление.

Каждый содержит только row_id,target,2246 уникальныхID строго в sample-порядке,
конечные значения[0,1]. Ранговые смеси — оценки ранжирования,калиброванность
вероятностей для AP не требуется. Сохранены веса,jobSHA и replay exact checks.
manifest.json указывает основной файл,источник каждого компонента и SHA CSV.

60 unit checks и 21 synthetic job проверяют полный путь до CSV. QA использует
только синтетические данные,не раскрывает Q2/Q3 реального набора. Все модели
после reload дают EXACT,21job resume без fit,CSV SHA совпадают;changed config
отвергается до перезаписи. QA-сгенерированные CSV не являются кандидатами.

Воспроизведение на сервере с CSV вdata/:

```bash
bash scripts/export_hw4_final.sh outputs/hw4/final-20261120 data cpu
```

Третий аргументcuda включает GPU только для VisitTransformer;CB остаётсяCPU.
Текущий опубликованный public model на сервере необязателен;при его отсутствии
reference42 переобучается с теми же параметрами. Локально можно использовать
--reuse-public-context /path/to/context-features-20261116 для экономии refit.
--resume пропускает только совпадающие source/data/config/environment/jobSHA.

## Распределение 15 попыток

- **День 1:** сначала основной A/B по замороженному правилу,затем второй;
  при полезной необходимости compact/context компоненты. До 4 содержательных

  при проверке на старом dev: MAP-orientedCB/TabM и полезная смесь. Не подбирать
  множество соседних весов по маленькому Public. Остальные слоты — резерв.
- **День 3:** проверить целостность/воспроизводимость,при необходимости 1–2
  финальных отправки и явно выбрать 2 для финального зачёта.
