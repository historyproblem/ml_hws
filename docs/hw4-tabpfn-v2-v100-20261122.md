# HW4. Проверка TabPFN V2 на V100

**Built with PriorLabs-TabPFN.** Подготовлены два фиксированных варианта локального прогноза. Оба используют один уже обученный checkpoint TabPFN V2. Качество на HW4 и время на V100 станут известны после фактического запуска. На Mac проверен весь путь на синтетических данных с реальными весами.

## Что вычисляет сервер

| Настройка | Принятое значение |
|---|---|
| Версия | tabpfn 2.2.1, Prior-Labs/TabPFN-v2-clf, публичный файл tabpfn-v2-classifier-v2_default.ckpt |
| Контекст | Из официального train взять более ранние кварталы, отсортировать по forecast_period и row_id по возрастанию, сохранить последние 10 000. Для test действуют тот же порядок и тот же предел. Частичный самый старый квартал выбирается по row_id независимо от target. |
| Представления | pfn_v2_compact94 включает compact96 без forecast_year и cutoff_gap_days. Категориальны тип заведения, риск, район и номер квартала. pfn_v2_full346 использует все базовые признаки, групповой контекст и исходные десять категорий. |
| Модель | Четыре внутренних ансамблевых компонента, random_state=42, исходные вероятности класса 1, один поток препроцессора. Обучающий контекст задаётся в fit. Градиентное обучение весов отсутствует. |
| Инференс | CUDA, float32, fit_preprocessors, memory_saving_mode=True. Начальный запрос охватывает весь предсказываемый квартал. При конкретном исключении CUDA OOM повторяются только запросные блоки размером 512, 128 и 32, меньшие исходного размера. Число контекстных примеров и четыре компонента сохраняются. Размер реально прошедшего блока записан в modelinfo. |
| Проверка | Три старых квартала 2023Q3, 2023Q4, 2024Q1 с AP, один test-прогноз и два прогноза 2024Q2/Q3 без расчёта AP для каждого из двух представлений. Всего двенадцать диагностических контекстов. |

Вторая пара кварталов добавлена по решению пользователя **до первого реального GPU-запуска**. Их прогнозы выводятся отдельным запечатанным результатом для однократной диагностики после фиксации списка финалистов. Предшествующие официальные обучающие метки по-прежнему доступны при построении следующего по времени прогноза. Ни поиск конфигурации, ни выбор веса смеси на Q2/Q3 в серверном раннере не реализованы.

Подтверждённое ограничение V2 — 10 000 контекстных строк и 500 входных столбцов. Оба представления укладываются в заявленную область. Границы не обещают конкретную задержку или успешное размещение модели в 32 ГБ. На V100 проверяются доступность CUDA, память и фактический повторный forward. Измерения из статьи на других устройствах неприменимы для прогноза времени этого запуска. [Статья авторов](https://www.nature.com/articles/s41586-024-08328-6) · [Дистрибутив 2.2.1](https://pypi.org/project/tabpfn/2.2.1/)

## Как изолированы зависимости и внешние веса

Запускатель создаёт отдельный venv, подключает CUDA Torch и научные библиотеки активного серверного Python для чтения и устанавливает перечисленные в репозитории колёса внутрь venv с --no-deps. Для HW4 ранее был подтверждён Linux x86_64, Python 3.12.9 и torch 2.6.0+cu126. В оригинальном колесе tabpfn 2.2.1 указаны torch >=2.1,<3 и scikit-learn >=1.2,<1.7. Поэтому внутри используется sklearn 1.6.1, в основной среде сохраняется sklearn 1.7.2. Взята версия tabpfn-common-utils 0.1.9. Предыдущую 0.1.8 отозвали с PyPI. Для всех 28 закреплённых дополнительных дистрибутивов проверено наличие подходящих колёс для Linux x86_64 Python 3.12. [Параметры окружения](../configs/hw4-tabpfn-v2-overlay.txt) · [Метаданные PyPI](https://pypi.org/pypi/tabpfn/2.2.1/json)

Публичный checkpoint занимает 29 009 539 байт. До использования проверяется SHA-256 cf8c519c01eaf1613ee91239006d57b1c806ff5f23ac1aeb1315ba1015210e49. В колесе прежним именем по умолчанию служит finetuned-zk73skhh. Авторы указывают, что это идентичная копия выбранного v2_default. Файл V2 допускает загрузку через torch.load с weights_only=True. Загрузчик берёт опубликованный файл напрямую без входа в Hugging Face. Данные HW4 остаются на сервере. Телеметрия отключена, локальный служебный timestamp направлен в рабочий каталог, сокетные соединения в процессе инференса блокируются. V2.5 имеет отдельные веса, условия и требования доступа, его запуск не входит в этот опыт. [Страница и SHA выбранного файла](https://huggingface.co/Prior-Labs/TabPFN-v2-clf/blob/main/tabpfn-v2-classifier-v2_default.ckpt) · [Модельная карточка и имена копий](https://huggingface.co/Prior-Labs/TabPFN-v2-clf) · [V2.5](https://huggingface.co/Prior-Labs/tabpfn_2_5)

У лицензии V2 есть дополнительное требование об атрибуции в разделе 10 и уточнение про внутреннее тестирование. Запускатель сохраняет копию лицензии рядом со скачанными весами. Веса и исходные данные в архив результатов и Git не включены. В прочитанных правилах HW4 разрешено разумное использование ИИ, отдельных условий именно про готовые модельные веса не обнаружено. Следует обозначать этот вариант как внешний pretrained checkpoint. [Лицензия V2](https://huggingface.co/Prior-Labs/TabPFN-v2-clf/blob/main/LICENSE.txt) · [Правила HW4](https://www.kaggle.com/competitions/hw-4-ml-mipt-autumn-2026/rules)

## Результат и воспроизводимость

Общий GPU-запускатель может вызвать scripts/run_hw4_tabpfn_v100.sh с выходным каталогом и каталогом четырёх официальных CSV. По умолчанию используются analysis/hw4-tabpfn-v100-01 и data. HW4_PYTHON указывает на исходный серверный Python с работающим CUDA Torch. Создание окружения и получение официальных пакетов и весов требуют доступа к PyPI и Hugging Face на первом запуске. После подготовки сеть для прогноза отключается. При нехватке памяти после всех допустимых размеров запросного блока раннер сохраняет завершённые контексты и выдаёт причину остановки. [Запускатель](../scripts/run_hw4_tabpfn_v100.sh) · [Расчёт и экспорт](../scripts/run_hw4_tabpfn_v100.py)

В return_results.tar.gz ровно семь обычных файлов: protocol.json, completion.json, old_oof.csv, test_predictions.csv, fold_metrics.csv, modelinfo.json и recent_predictions.csv. Только fold_metrics.csv содержит AP, ровно для шести старых сочетаний модели и квартала. В modelinfo сохраняются размеры, хеш и распределение учебных ID по кварталам, имена признаков, память, время и масштаб предсказательной порции для каждого контекста. Прогнозы recent содержат идентификаторы, период, официальную метку и две колонки вероятностей. Порядок test соответствует исходному test_student.csv, последующее формирование отправки должно сопоставлять row_id с образцом.

В изолированном Mac-окружении фактически прошли tiny-инференс и все двенадцать синтетических контекстов с настоящим V2 checkpoint. Проверены неизвестные категории, NaN, оба размера входа, точный повтор первого полного старого фолда, соответствие всех CSV сохранённым массивам, изоляция сети и содержимое архива. Синтетические all-NaN признаки вызывали предупреждения NumPy внутри библиотечного препроцессинга. Выходы были конечны. Четыре отдельных теста проверяют отбор последнего контекста без обращения к меткам, категории и пропуски, уменьшение только предсказательной порции при имитации OOM и состав архивных файлов. [Тесты](../tests/test_hw4_tabpfn_v100.py)
