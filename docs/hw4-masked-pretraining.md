# ДЗ4 Маскированное предобучение групп признаков

Следующий эксперимент после завершённого FT-пилота с AP0.259700.
Код реализован,17 тестов и короткий сквозной запуск пройдены.
Полное качество новых вариантов на V100 пока неизвестно.
Текущая опора: context-CatBoost dev0.268277, подтверждённый Public0.33982.

## Что сравнивается

1. `group_supervised`: групповая сеть обучается на таргете с нуля.
2. `group_masked`: та же сеть сначала восстанавливает скрытые группы,
   затем обучается на таргете. Контроль выделяет добавочную пользу предобучения.
3. `catboost_ssl64`: прежний CatBoost500/depth5/lr0.04/L2=10 получает346
   исходных признаков и64 дополнительных численных признака от замороженного
   кодировщика. Encoder фиксируется до любого обучения на таргете.

Основная идея восстановления повреждённых табличных данных описана в
[VIME](https://proceedings.neurips.cc/paper_files/paper/2020/hash/7d97667a3e056acab9aaf653807b4a03-Abstract.html).
Здесь используется собственная групповая архитектура и явные mask-токены;
это не буквальное воспроизведение VIME или языкового BERT.

## Представление признаков

Те же346 causal-признаков, что у context-CatBoost. Импутация и словари
обучаются только на fit. Числа дополнительно проходят train-only quantile
normalization к нормальному распределению, ограниченную[-4,4]; константы
fit превращаются в0. Исходные missing flags сохраняются отдельно.

Получается15 групповых токенов: календарь; объём, исходы, типы, давность и
коды/нагрузка своей истории;6 типов контекста других площадок;3 статические
категории. Категории имеют embeddings8. Каждая группа проецируется в96 чисел;
далее3 pre-norm блока Transformer,4 головы,FFN192,dropout0.15 и bottleneck64.
Классификатор также получает непосредственную табличную ветку.
Нормализация, архитектура и supervised optimizer одинаковы у двух neural-веток.

## Предобучение

Базовая вероятность скрытия группы0.35. Все её поля и missing indicators
заменяются одним обучаемым mask-токеном. Коды и производные количества/средние
своей истории находятся вместе. Все outcome-count/rate/result — тоже вместе.
При скрытии объёма визитов дополнительно скрываются коды/нагрузка, исходы и
типы: иначе число визитов можно восстановить точной арифметикой производных.
Связанные признаки из других временных окон остаются в той же группе.
Это защита от перечисленных прямых shortcuts, не гарантия отсутствия любых
статистических зависимостей между оставшимися группами.

Loss считается только по скрытым группам с равным групповым весом:
SmoothL1 для наблюдаемых нормализованных чисел,0.2×BCE для missing indicators,
нормированная cross-entropy для категорий. Функция pretrain не принимает target.
Восстановление скрытых исходов относится только к уже известной прошлой истории.
Целевой будущий исход, row_id и site_id исключены из входов.

20 фиксированных эпох предобучения, AdamW lr0.001/wd0.01. Никакого выбора
числа pretrain-эпох по внешней AP или Public. Затем AdamW lr0.0005/wd0.01,
batch256, максимум40 supervised-эпох, patience8; seed42.
Fine-tuning seed и optimizer сбрасываются одинаково для контроля и pretrain.

## Временная проверка и SSL-признаки

Внешние кварталы:2023Q3/Q4/2024Q1. Число supervised-эпох выбирается на
предыдущем внутреннем квартале. Затем модель с нуля проходит своё обучение
на всех ранних строках и оценивается один раз на внешнем квартале.

Каждый inner/outer pretrain обучается только на X своего fit. Ни X внешнего
квартала, ни test, ни закрытые2024Q2/Q3 в pretrain не поступают.
Весь preprocessing также переобучается внутри соответствующего fit.

Для `catboost_ssl64` сохраняются pretrained.pt и embeddings всех fit/valid
строк ДО fine-tuning. Эти признаки получены без Y; CatBoost затем обучается
на fit labels как обычно. Embeddings после supervised fine-tuning не подаются
в этот CatBoost. Для будущих supervised-embedding экспериментов потребуется
отдельное временное cross-fitting.

## Запуск V100

В активном окружении с уже установленным torch2.5.1+cu121:

```bash
python -m pip install -r configs/hw4-masked-requirements.txt
mkdir -p logs
nohup bash scripts/run_hw4_masked_v100.sh analysis/hw4-masked-v100-01 data \
  > logs/hw4-masked-v100-01.log 2>&1 &
tail -f logs/hw4-masked-v100-01.log
```

Все4 CSV лежат непосредственно в data/. Wrapper включает3 варианта и resume.
В логе видны CPU-подготовка, CUDA-device, каждый pretrain/fine-tune epoch,
первый batch и CUDA-память. CatBoost-этап выполняется на CPU.
Параметры одного ограниченного сравнения заданы заранее; перебора HPO нет.

## Сохранение и продолжение

В output сохраняются protocol.json с input/source/environment signature,
fold_metrics.csv, predictions.csv и summary.csv. Для каждого quarter/variant:
веса, preprocessing, model_args.json, inner/outer curves, OOF и job.json
с SHA каждого артефакта. У masked есть также frozen_ssl64.npz, pretrained.pt
и catboost_ssl64.cbm. Encoder, итоговые neural-веса, preprocessing и CatBoost
после загрузки проверяются точным повторением прогнозов на том же устройстве.

Повтор той же команды пропускает завершённые jobs после проверки SHA.
Незавершённый job пересчитывается с начала. Изменённые code/data/config/версии
не допускают resume в прежнюю папку: нужен новый output. JSON completion
markers записываются через atomic rename. Внешние epochs повторно не выбираются.

Скрипт создаёт CV-результаты. Финальный test-refit/CSV для Kaggle и загрузки
в этом прогоне не выполняются; выбирать кандидата будем по полным результатам.

## Проверено локально

17 тестов: прежние causal-проверки и новые проверки mask isolation, групповой
зависимости volume, train-only quantiles/unknown categories, запрета target,
градиентов bottleneck, неизменности supervised head при pretrain и независимости
замороженного encoder от последующих изменений модели.

Короткий запуск всех3 вариантов:32 строки на квартал,192 fit-строки первого
внешнего фолда,1 слой/width16,2 pretrain/2 maximum supervised эпохи.
Результаты smoke проверяют код, их AP не является оценкой полезности метода.
Resume переиспользовал2 полных jobs без обучения. Изменение mask probability
при resume отклонено с сохранением прежнего протокола.
