# Финальный рефит и ограниченные проверки

Конфиг `configs/final_checks.json` фиксирует основной ансамбль D2/F2 Joint Hurdle MLP (`compact_l2`, seed 42/123/2026). Код исходного `src/spend_baselines/` и `configs/v100_suite.json` не меняется: старые 289 заданий и их манифест сохраняют совместимость. Дополнения находятся в `scripts/final_check_*.py` и отдельном output-каталоге.

## Один запуск на V100

Сначала убедитесь, что старый последовательный/параллельный прогон остановлен. Команды из корня клона, в прежнем рабочем CUDA-окружении:

```bash
git fetch origin
git switch codex/final-checks
git pull --ff-only
bash scripts/run_v100_final.sh
```

Датасет остаётся в `data/raw`, исходный прогон — в `outputs/v100-focused`. Запускатор выполняет:

1. **Сначала основной рефит:** исходный Joint mean3 на всех доступных перед ноябрьским тестом метках. Выбор эпох использует октябрь; затем каждый seed обучается с нуля на полном допустимом D2. Проверенный файл сразу копируется в `outputs/final-checks-20261115/submissions/joint_mean3.csv`.
2. Рефит резервного Wide mean3. Формируются отдельные локальные CSV Wide и блендов 75% Joint / 25% Wide и 50/50. Веса относятся к log1p-прогнозам.
3. Ограниченные дополнительные проверки. Сначала сентябрь/октябрь, затем июнь–август. По умолчанию на этот этап отведено 90 минут; ограничение проверяется между заданиями. Основной CSV сохраняется независимо от того, завершён ли дополнительный план.

Для получения основных файлов без дополнительных обучений:

```bash
bash scripts/run_v100_final.sh --max-minutes 0
```

Никакой загрузки в Kaggle и автоматической замены основного кандидата нет. Использование десяти отправок нужно отслеживать отдельно.

## Зафиксированные проверки

| Проверка | Модель | Изменение относительно D2/F2 |
|---|---|---|
| `season_ridge`, `season_joint` | Ridge / Joint | Календарь и доступная годовая/ноябрьская история |
| `target_history_ridge`, `target_history_joint` | Ridge / Joint | Прошлые завершённые 30-дневные траты, доля нулей, сглаживание |
| `joint_l2_1e3` | Joint | Только L2: 0,0001 → 0,001 |
| `joint_dropout_10` | Joint | Только dropout: 0 → 0,1 |
| `joint_total_loss_2` | Joint | Только вес итогового log-MSE: 1 → 2; BCE и положительный MSE остаются 1 |

Всего 85 внешних оценок на пяти датах: 10 Ridge и 75 нейросетевых. Последние включают выбор эпох и повторное обучение, поэтому это 150 нейросетевых fit сверх рефитов основных кандидатов. Это отдельные заранее выбранные проверки, не произведение всех настроек и не автоматический поиск победителя.

**Сезонный блок** добавляет 24 признака к исходным 49 F2: доли календарных месяцев в будущем 30-дневном окне (известный календарь), суммы/частоту в соответствующем окне год назад, сезонные отношения, активность в ноябре предыдущего календарного года. Если соответствующий период не покрыт логами, значение NaN и флаг доступности 0; полное покрытие с отсутствием покупок даёт настоящий ноль. Отдельного наблюдаемого ноября 2018 в train нет, поэтому улучшение на Sep/Oct не доказывает специфический ноябрьский эффект.

**Target-history** добавляет 15 признаков: шесть прошлых завершённых 30-дневных log1p-таргетов, среднее/разброс/долю нулей и сглаженные оценки с силой prior 3. Приор строится отдельно для каждой даты только по исходным официальным train-ответам с `target_end <= as_of_date`. Будущие ответы, включая текущий target строки, в него не входят. Если доступного приора ещё нет, сглаженные значения отсутствуют и есть флаг доступности.

Все фактические разрешённые имена сохраняются в `feature_schema.json`: F2=49, F2+season=73, F2+target-history=64. Признаки и цель не смешиваются. Target/preprocessing, D2-веса клиент–месяц, inner/outer cutoffs и общая 30-дневная цель сохраняются.

## Отчёт и возобновление

- `submissions/joint_mean3.csv` — основной файл; `wide_mean3.csv`, `joint75_wide25.csv`, `joint50_wide50.csv` — локальные альтернативы.
- `reports/locked_blend_validation.csv` — проверка фиксированных весов на уже готовых прогнозах, без новых fit.
- `reports/scores.csv` — отдельные запуски; `candidate_scores.csv` — средние прогнозов seed с явными `seeds_done`, `seeds_expected`, `complete`.
- `reports/late2_comparison.csv` — объединённая RMSLE Sep/Oct, delta против основного Joint, парный bootstrap по клиентам и покрытие пяти дат. `pooled5_RMSLE` появляется только при наличии всех пяти дат.
- `checks/jobs/` — кривые, веса, прогнозы и SHA256 каждого завершённого задания. `status.json` показывает фактическое покрытие, не объявляя частичный прогон завершённым.

Малые изменения порядка 0,001–0,003 помечаются предварительными. Интервалы условные и не исправляют многократное использование Sep/Oct. Колонка `automatic_replacement` всегда false: решение остаётся за человеком.

Повтор той же команды с тем же кодом, данными, окружением и конфигом пропустит готовые задания. Изменение этих определений требует другого output-каталога. Ошибки сохраняются отдельно; основной файл не удаляется. Выполнение изолировано от старого плана 515 оценок.

Если конкретная новая проверка признана достойной финального рефита, её нужно выбрать явно:

```bash
python -u scripts/run_final_checks.py refit --device cuda --resume \
  --out-dir outputs/final-checks-20261115 --case target_history_joint
```

Команда создаст отдельный CSV этой модели; основной `joint_mean3.csv` не заменяется.

## Передать результаты для анализа

```bash
python scripts/export_final_checks.py --out-dir outputs/final-checks-20261115
```

Получится `outputs/final-checks-20261115/final-results.zip` с завершёнными прогнозами, кривыми и отчётом. Веса и крупные feature-cache в архив не входят.

## Локальная проверка реализации

```bash
python -m unittest discover -s tests -p test_final_checks.py -v
python scripts/run_final_checks.py plan
```

Прежняя joint loss при единичных коэффициентах и обучение повторены численно без изменения результата. Проверены отсутствие будущих транзакций/меток в дополнительных признаках, различение отсутствующей истории и нуля, сохранность основного CSV и логарифмическое смешивание. Короткие `--smoke`-прогоны проверяют код и не являются оценками качества полного обучения. CPU и CUDA могут выбирать разные эпохи; экспериментальные CPU-результаты не подменяют CUDA-подтверждение.

## Фактически выполнено локально, 15 ноября 2026

На CPU завершены все 34 приоритетных задания Sep/Oct: 4 Ridge и 30 Joint, по три seed у каждого нейросетевого варианта. Остальные 51 оценки на июне–августе не выполнялись. Построчные агрегаты сохранены в `docs/final-checks-cpu-scout.csv`; исходные прогнозы и манифесты — в локальном `outputs/final-checks-ridge-local-20261115/final-results.zip`.

| Вариант | Объединённая RMSLE Sep/Oct |
|---|---:|
| Зафиксированный Joint mean3, исходный CUDA-архив | 2,643943 |
| Season Ridge, CPU | 2,660876 |
| Season Joint mean3, CPU | 2,673645 |
| Target-history Ridge, CPU | 2,663464 |
| Target-history Joint mean3, CPU | 2,645781 |
| Joint L2=0,001, CPU | 2,663764 |
| Joint dropout=0,1, CPU | 2,660870 |
| Joint total-loss weight=2, CPU | 2,645729 |

Ни один новый вариант этого набора не обошёл основной на обеих датах. Сравнение CPU с CUDA не изолирует эффект изменения признаков или параметров, поэтому это предварительный отсев, а не CUDA-подтверждение. Окончательный выбор основного не менялся.

По исходным CUDA-прогнозам фиксированный бленд 75% Joint / 25% Wide даёт 2,641932 на Sep/Oct (Sep 2,625530, Oct 2,657391); 50/50 даёт 2,642442. Оба ухудшают октябрь относительно Joint; малая объединённая разница не служит основанием для замены.

Отдельно исходной командой `spend_baselines.suite refit` завершён полный CPU-рефит исходного D2/F2 Joint mean3. Резервный файл `outputs/final-checks-cpu-fallback-20261115/submissions/joint_mean3.csv` проверен: 3188 строк, точные Id и порядок sample_submission, конечные неотрицательные значения. Он не загружался в Kaggle; CUDA-рефит этим не объявляется выполненным.
