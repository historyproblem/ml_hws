# Подбор до дедлайна: только семинары1–10

У пользователя осталось около2.5часов на фиксацию решения и однаV100.
Этот запуск оставляет время на финальный файл и сдачу: сначала создаёт
допустимый запасной CSV одиночного MLP, затем ограничивает поиск65минутами.
Последняя начатая оценка может закончиться немного позже лимита. Финальный
рефит выбранного кандидата выполняется отдельно после поиска. Upload не автоматизирован.

```bash
git pull --ff-only
python -m pip install -e .
bash scripts/run_course10_fast_tuning.sh
```

По умолчанию два независимых процесса на однойV100. У каждого собственные
seed/RNG/модель. Прогнозы процессов не смешиваются. При нехватке CPU/RAM:
`bash scripts/run_course10_fast_tuning.sh 1 65`.

## Что подбирается

Ручной список25профилей:12обычныхMLP (lr/L2/dropout/batch и две проверки
небольшой ёмкости),8RandomForest (depth/leaf/features/trees),5Ridge(alpha).
Это знакомый по семинарам3/9 ручной перебор параметров, без AutoML,
бустинга, Joint/hurdle, блендов, mean3 или товарных нейронных веток.
Данные D0/F0: только официальные месячные строки и15RFM-признаков.

1. Seed42 всех профилей сравнивается на June/July/August. Три исходных
   контроля на этих датах переиспользуются, если окружение совпало с архивным.
2. Top2MLP и top2лесов плюс их исходные контроли проверяются с seed123/2026
   на тех же ранних датах. Усредняются **ошибки отдельных моделей**,
   не их прогнозы. Это оценка устойчивости процедуры обучения.
3. Для каждой семьи фиксируются настройки, затем ранний общий победитель
   записывается в winner.json. Параметры не выбираются по Sep/Oct.
4. Три семейных победителя проходят September/October с фиксированным seed42.
   Дополнительно выполняется небольшой диагностический replay November2017
   из внутренних данных. Это ретроспективная диагностика уже выбранных HP,
   а не независимая оценка всей процедуры выбора в2017году: HP подобраны
   по более поздним2018срезам, обучающей истории тогда было меньше.
   Это не новая ноябрьская метка теста2018 и не основание
   подобрать поправку по Kaggle2.77883.
5. Общий ранний победитель рефитится на всех доступных к2018-11-01 метках.
   Финальная модель **одна, seed42, один регрессионный выход**.

Нейросетевой fit сохраняет прежнюю temporal selection/refit схему. Лес
разрешён семинаром9, несмотря на внутреннее ансамблирование деревьев.
Остальные ссылки и строгие границы: [course10-only.md](course10-only.md).
Даты раньше просматривались, интервалы условные и не корректируют selection/drift.

## Результаты

* Запасной допустимый файл: `outputs/course10-only/refit/mlp/submission_course10_mlp_seed42.csv`.
* Выбранный по ранним датам кандидат: `outputs/course10-fast-tuning/selected_refit/submission_course10_tuned_<model>_seed42.csv`.
* `scores.csv` показывает каждый seed отдельно; mean3-прогнозов нет.
* `confirmation_scores.csv` содержит paired comparison/CI для seed42 относительно исходной одиночнойMLP.
* `shortlist.json`, `winner.json`, кривые/построчные прогнозы и временные границы сохраняются.
* `course10-tuning-results.tar.gz` создаётся автоматически без весов/кэшей, со SHA экспортированных артефактов.

При остановке по лимиту остаются все завершённые оценки и запасной CSV.
`status.json.complete=false` означает, что выбранного полного кандидата ещё
нет. Тот же вызов с resume продолжает работу; число workers и ресурсный
лимит можно менять без изменения математической конфигурации.

**Не отправляйте все полученные варианты.** Пришлите архив для проверки,
затем используем один обоснованный кандидат. Ранний победитель может
не подтвердиться на последних датах; запасной файл поэтому сохраняется.
Четыре Kaggle-попытки поиском и рефитом не расходуются.

Ручной snapshot после прерывания:

```bash
python scripts/tune_course10_fast.py export --out-dir outputs/course10-fast-tuning --archive course10-tuning-results-2.tar.gz
```

Smoke использует64клиента/2эпохи/3дерева и отдельный output. Его файлы имеют
`upload_ready=false`, не являются качественными результатами и не подаются в Kaggle.
