## Как устроены варианты

**Нелинейный Ridge.** Из83 прежних входов строятся непрерывные кусочно-линейные функции. Узлы — уникальные обучающие квантили0/.2/.4/.6/.8/1. Календарь и coverage не разворачиваются; константы пропускаются. За пределами обучающего диапазона функции насыщаются. Вторая карта добавляет произведения функций для трёх заранее выбранных пар: recency×n90, recency×mean_log_spend6, year_spend30×recency. Это фиксированное нелинейное отображение и один Ridge, по принципу отображения признаков из семинара7 и L2-регрессии2/6. Реализация базиса авторская; утверждения, что именно эти ramp-функции написаны в семинаре, нет.

Из alpha10/100/1000 на июне–августе выбраны100 для отдельных эффектов и10 для взаимодействий. Выбор сохранён до запуска Sep/Oct. Финальные карты имеют281/321 регрессионный признак. Расчёт коэффициентов — float64/Cholesky.

**Прямой SKU-Ridge.** За180дней до каждого объекта учитывается по одному item-событию на покупательский день; вес2^(−age/90), затем log1p суммы. Использован существующий причинный builder из прогона SVD; новая SVD/эмбеддинг не обучается. Словарь выбирается только по purged TRAIN: минимум10 разных клиентов, а не10 повторных snapshot-строк. Суммарный L2-нормированный товарный блок имеет масштаб5; дополнительно доля известной товарной массы и log-число уникальных товаров. В ноябрьском refit3640товаров.

Alpha1000 выбрана на ранних датах. Один Ridge/LSQR, float64, tol1e-7/max500; сходимость проверена. Контроль с тем же alpha и двумя скалярами, но без SKU, даёт2.629895 против2.629342 с SKU; delta−0.000552, CI[−0.006499,+0.005078]. Самостоятельная полезность идентичностей не подтверждена.

**Совместный Ridge.** Два блока объединены в один вектор, а не в ансамбль прогнозов. Ранние alpha10 и1000 перенесены без нового поиска. При общем Ridge-alpha10 масштаб SKU уменьшен с5 до0.5: это эквивалентно штрафу1000 в исходном товарном масштабе и10 для табличной части. Эквивалентность проверена против явной диагональной матрицы штрафов.3963признака, один fit. После полученного Kaggle-ухудшения новые варианты этой ветки не рекомендуются.

**Шкала ответа MLP.** Та же сеть128/64, seed42/lr.001/L2.003/dropout.1/batch1024, те же83входа. На каждой обучающей части отдельно рассчитываются mean/std log1p(target), сеть обучается на стандартизованном отклике. Валидационные ответы остаются исходными: early stopping измеряет RMSLE после обратного преобразования. Финал: z=max(0,mean+std*raw), y=expm1(z). Это не дата-центрированная рыночная модель: здесь всего два TRAIN-скаляра, без ноябрьского коэффициента. Сохранение/загрузка включает эти скаляры. Численно прежний L2 оставлен; нормировка меняет динамику и взаимодействие со штрафом, поэтому чистая эквивалентность регуляризованной нейросети не предполагается. Локально выигрыша нет; фактический Kaggle-результат2.71080/2.67616 также хуже лучших.

Все fit используют только target_end<=cutoff; каждый raw bag и каждый месячный вход используют event_ts<as_of_date. Неизвестный SKU не получает выученного коэффициента. Глобальные имена колонок в сыром sparse-cache — технические коды; обученный словарь и нормировка используют только доступные TRAIN-истории. Внешние транзакции не использовались.

## Проверки и команды

В `analysis/nonlinear-regression-20261116/` сохранены скриншоты/JSON двух фактических Kaggle-результатов, проверки CSV, matched-абляция SKU и проверки воспроизведения. В `outputs/nonlinear-ridge/`, `sparse-item-ridge/`, `ramp-item-ridge/`, `target-scaled-mlp/` — построчные forecasts, scores/slices/bias, модели, ранние selections и время каждого fit/inference.

Для финального CPU-рефита MLP:
```bash
python scripts/run_target_scaled_mlp.py --refit-only --out outputs/target-scaled-mlp-refit
```

Для воспроизведения нелинейного Ridge:
```bash
python scripts/run_nonlinear_ridge.py --refit-only --profile ramp_interactions --alpha 10 --out outputs/nonlinear-ridge-refit
```

Используются официальные CSV в data/raw и существующий D2 base-cache по умолчанию outputs/behavior-cpu-screen/base_cache; иной путь передать через --cache. Вычисления выполнялись локально на CPU. Новых ноутбуков и автоматических Kaggle-загрузок нет. Базовый предиктор не менялся.


Шесть целевых тестов и четыре smoke-прогона прошли. Пять финальных CSV повторно проверены по всем SHA,3188 Id, порядку/схеме, finite/nonnegative/expm1 и точному forward сохранённых моделей. Финальные рефиты нелинейного Ridge, комбинированного Ridge и MLP с нормировкой ответа повторены с нуля: CSV побайтно совпали. Эти проверки подтверждают воспроизводимость, а не выигрыш на неизвестных ноябрьских ответах.
