# Строгий рецепт: семинары 1–10

Действующее указание пользователя: **использовать только методы до семинара
10 включительно**. Оно заменяет прежнее более широкое разрешение на
исследовательские модели. Проверена текущая версия курса
[`8a20cdf4b981c2962ef9741821b8d811468cf849`](https://github.com/andriygav/MachineLearningSeminars/tree/8a20cdf4b981c2962ef9741821b8d811468cf849),
а не только названия из плана. Код ноутбуков не исполнялся.

## Подтверждённые методы

| Метод | Источник | Что используем |
|---|---|---|
| Линейная регрессия с L2 | [семинар 2](https://github.com/andriygav/MachineLearningSeminars/blob/8a20cdf4b981c2962ef9741821b8d811468cf849/sem2/main.ipynb), [семинар 6](https://github.com/andriygav/MachineLearningSeminars/blob/8a20cdf4b981c2962ef9741821b8d811468cf849/sem6/main.ipynb) | Ridge, одна модель |

| Регрессия MLP с одним выходом и MSE | [семинар 8](https://github.com/andriygav/MachineLearningSeminars/blob/8a20cdf4b981c2962ef9741821b8d811468cf849/sem8/main.ipynb) | Прямой прогноз log1p(target) |
| Решающее дерево, RandomForest | [семинар 9](https://github.com/andriygav/MachineLearningSeminars/blob/8a20cdf4b981c2962ef9741821b8d811468cf849/sem9/main.ipynb) | Один RandomForestRegressor |

Семинар9 явно описывает регрессионные листья и forest; его можно использовать,
хотя лес сам является ансамблем деревьев. В том же семинаре есть комитеты
логических правил. Это не повод считать любой произвольный бленд рассмотренным
в курсе; в строгом рецепте собственные композиции моделей отсутствуют.

До10 также есть метрическая регрессия/Надарая–Ватсон (4), SVR (5), PCA/SVD (6),
нелинейная регрессия и нестандартные потери (7), ассоциативные правила (10).
Их не нужно добавлять только ради увеличения числа методов.

## Какие прежние надстройки убраны

* `mean3`, бленды и customer-bootstrap ансамбли: общий разбор усреднения
  моделей находится в [семинаре11](https://github.com/andriygav/MachineLearningSeminars/blob/8a20cdf4b981c2962ef9741821b8d811468cf849/sem11/main.ipynb).
  Мы не переносим этот рецепт на несколько MLP без прямого основания до10.
* Joint/hurdle, ZILN, survival, BG/NBD, Gamma-Gamma, mixture-of-experts,
  коррекция обученными индивидуальными остатками: прямого разбора этих
  готовых схем в1–10 не найдено; в активном варианте их нет.
* RNN/GRU/LSTM/TCN и Wide/residual-ветки не входят в выбранный обычный Perceptron.
* В семинаре7 действительно есть текстовые эмбеддинги, TripletLoss и пример
  предобученного LaBSE. Поэтому утверждать, что любые embeddings появляются
  только после10, неверно. Но наша обучаемая item-таблица с recency pooling
  не повторяет тот пример. В строгом рецепте она исключена; внешнее
  предобучение и трансформеры также остаются запрещены исходными условиями.

Это **консервативная граница нашего финального решения**, а не утверждение,
что организатор формально запретил все возможные комбинации знакомых блоков.
Упоминания MLP и произвольных функций потерь сами по себе не используются
как разрешение на любую специальную архитектуру. Старый отправленный
Joint+history mean3 не объявляется подтверждённо соответствующим новой границе.

## Данные и признаки

Выбран минимальный вариант D0/F0: только50852 официальных месячных train-строки,
15 вручную построенных RFM/календарных признаков, seed42. Никаких дополнительных
недельных обучающих объектов, target encoding/history, learned customer/item
vectors или регионального hashing в этом варианте нет. Это ограничение
пресета для простоты защиты, а не утверждение, что любая генерация признаков
запрещена: она рассматривается в семинаре8.

`log1p(target)` и MSE выбраны непосредственно из формулы RMSLE. После прогноза
используются `maximum(z,0)` и expm1. Признаки строго до as_of_date;
train содержит только `target_end <= cutoff`. Масштабирование/заполнение
пропусков обучаются на train. Число эпох MLP выбирается на более ранней
внутренней дате, затем сеть обучается с нуля. В финале **одна сеть, один выход**.

## Воспроизведение

Показать разрешённый план и пересчитать таблицу из прежних результатов:

```bash
python -m spend_course10 plan
python -m spend_course10 compare --reference outputs/v100-focused
```

Подготовить один финальный проверенный по схеме MLP на V100:

```bash
git switch codex/full-experiment-suite
git pull --ff-only
python -m pip install -e .
bash scripts/make_course10_submission.sh
```

Это только выбор эпох и рефит одной MLP, не новый большой экспериментальный
набор. Результат:

```text
outputs/course10-only/refit/mlp/submission_course10_mlp_seed42.csv
```

Рядом сохраняются model/preprocessing, предсказания, кривые, проверка полных
test Id/порядкаsample и result.json с картой семинаров. Upload в Kaggle не
выполняется. Пользовательский остаток4попытки этим не расходуется.

Альтернатива одним RandomForest на CPU: `bash scripts/make_course10_submission.sh forest`.
Ridge: тот же вызов с `ridge`. Они также входят в подтверждённый список.
Стандартный MLP — default по имеющимся локальным сравнениям, а не по
единственному полученному leaderboard score.

Для исходного ZIP можно передать `--reference intermediate-results-20261115-082812.zip`;
на этапе refit потребуется `--base-cache outputs/v100-focused/cache`.
`--resume` проверяет совпадение определения и SHA завершённых артефактов.
Smoke сохраняет `smoke_predictions.csv` с `upload_ready=false`, не submission.
Старые `make_joint_history_submission.sh`, `make_item32_submission.sh` и CLI обоих exporters
отключены для текущего режима; функции чтения/аудита старых результатов
сохранены для воспроизводимости. Предыдущие исследовательские веса и
результаты не удаляются.
