# RBF: техническое изменение convergence budget до OUTER

22 ноября 2026, согласовано root до первого внешнего результата. Изначальные [восемь RBF-рецептов](hw4-rbf-final-family-plan-20261122.md) не меняются по C, gamma formula/multiplier, view, log/imputation/RobustScaler/OHE, tol1e-3, class weighting, kernel, Platt calibration или RNG.

Первый run `analysis/hw4-six-hour-20261122/rbf/` остановился на девятом INNER-fit: own22/C5/gamma multiplier.25, FIT13013 перед предыдущим inner для outer2024Q1. Native solver дал ConvergenceWarning при cap100000; wrapper правильно отверг частичную модель. До этого было8 успешных INNER, **0 OUTER-fit и0 OUTER-метрик**. У той же C5/gamma.25 на9293/11101 строках final-margin n_iter78259/98566: лимит был слишком близок к достигнутому числу итераций. Synthetic5000 probe этого не выявил (11621 iterations).

Единственное изменение модельного алгоритма — максимальный технический cap **100000→1000000**. Convergence tolerance не меняется; cap не означает обязательное выполнение1M итераций. Это численная admissibility, не дополнительный AP-search и не разрешение partial model. Больше cap не увеличивается, новые семейства не добавляются.

Новые immutable файлы: `rbf_convergence.py`, `run_hw4_rbf_convergence.py`; новые output/freeze в `analysis/hw4-six-hour-20261122/rbf-convergence/`. Прежние source/output/freeze и8 моделей сохранены. Все24 INNER выполняются заново с единым source/budget: мы не смешиваем модели разных лимитов и внутренние five-fold calibration traces, не отбираем только удачные старые folds. Отчёт первоначального сбоя `rbf-invalid-before-outer.json` и его SHA включены в новый freeze. Фактический расход первого run: **9 estimator-fit attempts =8 завершённых+1 numerical-invalid**, отдельно от нового run.

При cap1M каждый ConvergenceWarning/nonzero status получает явный `budget_invalid` record, AP/logloss=None, без сохранения модели. Для каждого INNER выбирается только среди его valid recipes; сам оцениваемый квартал не удаляется. Full aggregate допускает только recipe, валидные на всех трёх INNER. Если в каком-либо INNER нет valid recipe либо нет ни одного полностью валидного recipe, процесс останавливается до OUTER. OUTER/full convergence failure сохраняет error и останавливает run без замены рецепта или partial score. Низкий AP никогда не является численной причиной исключения. Strict resume проверяет SHA valid и invalid records и не запускает их повторно.

7 runner tests покрывают обе обычные ветки gate, точный reload/resume/tamper, INNER-only selection, отсутствие модели/метрик у invalid, неизменность всех кварталов, all3 full validity и остановку при OUTER failure. Backend synthetic checks5 PASS; отдельный native2000/5000 probe нового cap сохранён до HW4. Независимый source-review подтвердил, что иных изменений гиперпараметров нет. Все дальнейшие raw/fixed75%07+25%RBF продукты, старые внешние кварталы, gate и GAM guard остаются прежними. Никаких новых внешних Q2/Q3-метрик или Kaggle uploads.
