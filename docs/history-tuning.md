# Подбор гиперпараметров Joint + history

> Архив исследований. Joint+history/mean3 не входит в текущий строгий рецепт
> до семинара10; активный маршрут описан в [course10-only.md](course10-only.md).

Опора — проверенный CUDA `joint_history_mean3`: pooled September–October
**2.624691**, пять дат **2.480971**, seed **42/123/2026**.
Это F2 (49 признаков) + четыре причинных признака истории меток:
число доступных месячных меток, сглаженные log-mean/доля нулей и EWMA.

Меняются параметры оптимизации и регуляризации одной сети 128/64.
Представление данных, history prior=5/half-life=90, D2, веса клиент–месяц,
двухчастный `hurdle_joint` loss, Adam и preprocessing сохраняются.
Эмбеддинги отложены до разбора этого подбора. AutoML, случайного или
декартова поиска архитектур нет.

## Восемь заранее заданных вариантов

| Профиль | Learning rate | L2 | Dropout | Batch size |
|---|---:|---:|---:|---:|
| baseline, готовый контроль | 0.001 | 0.0001 | 0 | 1024 |
| lr_half | 0.0005 | 0.0001 | 0 | 1024 |
| lr_double | 0.002 | 0.0001 | 0 | 1024 |
| l2_1e3 | 0.001 | 0.001 | 0 | 1024 |
| l2_1e2 | 0.001 | 0.01 | 0 | 1024 |
| dropout_005 | 0.001 | 0.0001 | 0.05 | 1024 |
| batch_512 | 0.001 | 0.0001 | 0 | 512 |
| regularized_slow | 0.0005 | 0.001 | 0.05 | 1024 |

Максимум 200 эпох, patience=20, min_delta=0.0001. На каждой дате сначала
выбирается число эпох на последней доступной более ранней официальной дате,
потом выполняется повторное обучение с нуля на всех метках `target_end <= cutoff`.

## Порядок выбора

1. **Screening**: семь новых вариантов с seed42 на June/July/August 2018.
   Всего 21 seed-оценка. Top2 определяются по pooled RMSLE, с весом строки,
   а не простым средним трёх месячных RMSLE. Они фиксируются в `shortlist.json`.
   На этом этапе варианты ранжируются между собой; готовый контроль mean3
   не сравнивается как будто это отдельный seed42.
2. **Mean3**: для двух выбранных вариантов добавляются seed123/2026 на тех же
   трёх датах. Это ещё 12 оценок; seed42 не обучается повторно. Их mean3
   сравнивается с готовым baseline mean3. Если выигрыш на ранних датах меньше
   0.001 RMSLE, остаётся baseline. Решение записывается в `winner.json`.
3. **Подтверждение**: только после фиксации `winner.json` выбранные настройки
   проходят September/October с тремя seed: максимум шесть оценок.
   Если выбран baseline, его готовые результаты переиспользуются и новых
   обучений на поздних датах нет. Поздние результаты не меняют выбранные HP.

Максимум **39 новых seed-оценок / 78 neural fit**. Это ограниченный поиск;
глобальная оптимальность HP не утверждается. Предварительный выбор с одним
seed экономит время, но может отсеять вариант из-за случайности seed42.

Таргет August заканчивается 31 августа — он доступен до первой подтверждающей
даты 1 сентября. Для каждого fit train purge и нормализация весов выполняются
заново. Все признаки используют историю строго до своей даты. Новый запуск
независимо проверяет весь кэш четырёх history-признаков по причинным prefix sums.

September/October уже использовались в предыдущих исследованиях. Это
подтверждающий этап текущего подбора, а не новый нетронутый holdout. Bootstrap
интервалы условные, без поправки на адаптивный выбор, множественные сравнения
и временной drift. Качество на ноябрьском тесте неизвестно.

## Запуск на V100

Из корня того же репозитория, где остались `outputs/behavior-v1` и старый
F2 cache `outputs/v100-focused/cache`:

```bash
git pull --ff-only
python -m pip install -e .
bash scripts/run_history_tuning_v100.sh
```

Результаты пишутся в новый `outputs/history-tuning-v1`. Старые результаты,
модели и конфиги не изменяются. Читаются готовые history/прогнозы контроля;
пересборки transaction features и повторных OOF Ridge нет.

Запускатор по умолчанию ограничен 90 минутами. Проверка лимита выполняется
между завершёнными seed-оценками, поэтому текущая оценка может выйти за лимит.
Повтор той же команды с `--resume` продолжит работу, сохранив уже готовые fit.
Параллельные процессы в одном output запрещены файловой блокировкой.

После остановки по лимиту `status.json` содержит `phase_complete=false`;
неполный результат не считается завершённым подбором. Если архив уже есть,
новый snapshot надо сохранить под другим именем:

```bash
bash scripts/run_history_tuning_v100.sh outputs/behavior-v1 outputs/history-tuning-v1 history-tuning-results-2.tar.gz
```

Четвёртый аргумент меняет лимит в минутах; 0 отключает его.
Изменение лимита не меняет математический fingerprint.

Можно использовать скачанный tar вместо исходного каталога. Тогда явно
укажите полный F2 cache:

```bash
python -m spend_tuning run \
  --reference behavior-results.tar.gz \
  --base-cache outputs/v100-focused/cache \
  --out-dir outputs/history-tuning-v1 --device cuda --threads 2 --resume
```

Отдельные этапы: `screen`, затем `confirm`; `run` выполняет оба. Манифест
связывает код, данные, версии, устройство, конфиг и кэши. Изменение этих
параметров требует нового output-каталога. Нельзя продолжать полный CUDA run
из CPU smoke output. Исходные `spend_baselines`/`spend_behavior` не изменены,
поэтому их прежние fingerprints сохраняются.

## Что скачать

После штатного запуска в корне появится **`history-tuning-results.tar.gz`**:
скачайте его через файловый браузер Jupyter и пришлите для проверки результатов.
`zip` не требуется. Экспорт можно повторить вручную, в том числе для
промежуточного snapshot:

```bash
python -m spend_tuning export --out-dir outputs/history-tuning-v1 --archive history-tuning-results-2.tar.gz
```

Архив содержит проверенные завершённые seed-прогнозы и кривые, средние трёх
seed, решения shortlist/winner, параметры, метрики, срезы 0/1–2/3+ покупательских
дней и нулевых/положительных целей, времена fit/inference и контрольные суммы.
Веса и feature caches остаются на сервере. Незавершённые и повреждённые jobs
не включаются, а перечисляются в export_manifest.json. Сводки — live snapshots;
окончательные метрики можно восстановить из построчных прогнозов.

Основные файлы: `screen_scores.csv`, `shortlist.json`, `winner.json`,
`scores.csv` (каждая дата и pooled tuning/confirmation/пять дат при полноте, с delta и bootstrap CI
к текущему Joint+history), `error_slices.csv`, `timing.csv`, `confirmation.json`,
`REPORT.md`. Победитель раннего отбора не заменяет основной вариант автоматически:
сначала разбирается подтверждающий результат.

## Последующий рефит

После разбора подтверждения, отдельной командой:

```bash
python -m spend_tuning refit --profile winner \
  --reference outputs/behavior-v1 \
  --out-dir outputs/history-tuning-v1 --device cuda --threads 2 --resume
```

Для сохранения прежних HP можно указать `--profile baseline`.
Финальные эпохи выбираются на последней доступной месячной дате перед тестом;
затем три модели обучаются на всех доступных метках и усредняются в log1p.
Результат — `refit/<profile>/predictions.npz` с Id, z и неотрицательным expm1(z).
**Submission CSV не создаётся, отправки в Kaggle нет.**

Smoke для проверки программы (64 клиента, две эпохи; качество несодержательно):

```bash
python -m spend_tuning run --smoke --device cpu \
  --reference behavior-results.tar.gz --base-cache outputs/v100-focused/cache \
  --out-dir outputs/history-tuning-smoke --resume
```
