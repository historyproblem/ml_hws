# Три независимых проверки на V100

22 ноября 2026. Подготовлены TabM с тремя вариантами обработки признаков,
TabPFN V2 и TabICLv2. Реальные серверные время, память и качество станут известны
после запуска пользователем. На Маке проверены настоящие модели на синтетических
данных, сохранение, повторный прогноз, архивы и возобновление.

## Запуск

На сервере нужен прежний Python с доступной V100, Torch 2.6/CUDA и четырьмя
официальными CSV прямо в `~/ml_hws_hw4/data/`. Новый launcher сохраняет текущие
Torch/CUDA и научные пакеты. TabM добавляет только две небольшие библиотеки
`--no-deps`. Для TabPFN и TabICL создаются отдельные окружения.

```bash
bash <<'HW4_RUN'
set -e
cd ~/ml_hws_hw4
git pull --ff-only origin codex/hw4-final-four
mkdir -p logs
nohup bash scripts/run_hw4_extended_v100.sh \
  analysis/hw4-extended-v100-01 data \
  > logs/hw4-extended-v100-01.log 2>&1 < /dev/null &
HW4_RUN
```

Лог:

```bash
tail -n 50 -f ~/ml_hws_hw4/logs/hw4-extended-v100-01.log
```

Готовый общий архив:

```text
~/ml_hws_hw4/analysis/hw4-extended-v100-01/return_results.tar.gz
```

Его пользователь передаёт обратно для локальной проверки. Отдельные архивы
также лежат в подпапках `tabm`, `tabpfn`, `tabicl`. Launcher выполняет этапы
последовательно, защищает весь запуск от дубликата и сохраняет успешные архивы,
если другая ветка завершилась ошибкой. Общий manifest содержит статус каждой.

## Что именно считается

| Ветка | Фиксированные варианты | Объём |
|---|---|---|
| TabM | clip/full346; quantile-normal/full346; quantile-normal/compact94 | 9 inner +27 outer +9 full +18 recent =63 fit |
| TabPFN V2 | compact94 и full346; последние 10 000 доступных строк | 12 inference-контекстов |
| TabICLv2 | compact94 и full346; весь доступный prefix | 12 inference-контекстов |

У TabM используются официальный TabM 0.0.3 и rtdl-num-embeddings 0.0.12,
32 участника, 3 блока по256, FP32, прежний AdamW. Число эпох выбирается только
на предыдущем внутреннем квартале seed42. Свежие outer-модели с seed42/17/2026
обучаются для выбранного числа эпох; полный fit использует медиану старых
внутренних выборов. Ни лучший seed, ни его подмножество не выбираются.

TabPFN и TabICL используют по4 компонента, seed42 и публичные веса с проверяемым
SHA. Вычисления локальны на сервере; API для передачи таблиц не используется.
Код TabPFN: **Built with PriorLabs-TabPFN**. Веса и зависимости не публикуются
в этом репозитории. [TabPFN: версии, лицензия и QA](hw4-tabpfn-v2-v100-20261122.md),
[TabICL: версии, лицензия и QA](hw4-tabicl-v2-v100-20261122.md).

Каждая ветка возвращает ровно семь обычных файлов. Внешний архив содержит
три внутренних архива и manifest с их SHA. Ни веса, ни pickle-объекты моделей
передавать обратно не требуется.

## Отложенная проверка последних кварталов

Пользователь поручил принять решение о дополнительной диагностике2024Q2/Q3.
Принято: один раз сравнить заранее зафиксированных финалистов, без настройки
параметров и весов по её результатам. Эти кварталы уже использовались20 ноября,
поэтому их нельзя объявлять новым независимым holdout.

GPU producer возвращает `recent_predictions.csv`, но не вычисляет для него AP
и не принимает на его основе решений. Перед каждым recent-прогнозом model fit
использует только более ранние официальные периоды. У TabM применяется заранее
зафиксированное число эпох полного рецепта; у foundation-моделей параметры
также неизменны. Старые три development-квартала оцениваются отдельно.

Все полные серверные прогнозы пока диагностические. Допуск с точными локальными
опорами04/07 и дополнительная диагностика выполняются после получения архива.
Серверный код не загружает submissions в Kaggle и не меняет финальные флажки.
