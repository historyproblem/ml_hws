# Отдельный вектор клиента из истории покупок

Офлайн-опыт по просьбе пользователя 15 ноября 2026. Цель — проверить
клиентский вектор как дополнительный вход предиктора расходов. Это отдельная
проверка представления: прежний item32 строил вектор внутри Joint-модели,
а здесь вектор обучается без таргета и затем используется обычной MLP.

История клиента на каждую дату превращается в строку матрицы
«клиентский snapshot × товар». Берутся положительные товарные покупки за
`[t−180 дней,t)`, по одному событию товара за покупательский день, с весом
`2**(−age_days/90)`. Значения — `log1p` суммы весов. Отмены, возвраты,
служебные и подарочные позиции исключаются по прежнему контракту очистки.

Словарь содержит только товары из историй обучающих строк. Строка
нормируется по L2 на этом словаре; неизвестные товары не дают входа.
TruncatedSVD32 обучается на обучающей части, без расходов/таргета. Для
inner selection и outer refit строятся разные словари и разные SVD.
Одни и те же оси inner не переносятся в outer: там сеть обучается заново.

Сравнение фиксировано заранее:

* Контроль: 15 RFM/календарных признаков F0 → MLP128/64.
* Опыт: те же F0 + 32 SVD-координаты клиента → такая же MLP128/64.

Только официальные месячные строки D0, seed42, один выход, MSE на
`log1p(spend_30d)`, Adam lr.001/L2.0001/dropout0/batch1024. Число эпох
выбирается на предыдущей доступной месячной дате, max200/patience20.
После выбора сеть обучается с нуля на всех метках, доступных к внешнему
cutoff. Внешние даты — 1 сентября и 1 октября. Размер32 и прочие параметры
не подбираются. Нет target-history, customer_id lookup, Joint/hurdle,
mean3, бленда моделей, бустинга или внешних данных.

Используемые блоки относятся к материалам курса: PCA/SVD — семинар6,
обычная MLP — семинар3 и регрессия с MSE — семинар8. Новые товарные признаки
являются отдельной исследовательской гипотезой, а не автоматическим
изменением минимального финального пресета `course10_safe.json`.
Курс зафиксирован на `8a20cdf4b981c2962ef9741821b8d811468cf849`;
сохранённые первичные материалы — в `research/course10-audit-20261115/`.

Локальный запуск из корня репозитория:

```bash
.venv/bin/python -u scripts/run_customer_svd.py
```

CPU используется по умолчанию; на V100 можно передать `--device cuda`
и новый `--out-dir`. Завершённые jobs проверяются по SHA и переиспользуются.
`--smoke` — 64 клиента и две эпохи только для проверки программы;
результаты этого режима не используются для вывода о качестве.

В `outputs/customer-svd-v1-cpu/` сохраняются manifests/входные SHA,
кэш историй, модели и SVD, клиентские validation-векторы, кривые выбора эпох,
построчные парные прогнозы и `scores.csv`. Интервал разницы RMSLE получен
2000-повторным bootstrap по клиентам совместно на обеих датах. Он условный:
даты ранее использовались, это не новый holdout и не оценка November.
Сравнение использует один seed, поэтому влияние инициализации не изолировано.

Тестовые November-прогнозы, submission.csv и Kaggle upload не создаются.
Финальный preset и архивные submission guards не меняются.
